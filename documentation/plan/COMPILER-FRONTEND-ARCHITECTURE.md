# C-plus Compiler Frontend: Target Architecture

Status: architecture plan, not a normative language specification. Existing behavior remains authoritative until a phase is implemented and its acceptance gate passes. Track implementation in [`COMPILER-FRONTEND-IMPLEMENTATION.md`](COMPILER-FRONTEND-IMPLEMENTATION.md).

## Goals and boundaries

The compiler should parse C-plus structurally, retain exact source provenance through every transformation, and continue emitting portable C for the existing TinyCC/system-compiler backends. Parser choice must not leak into language lowering. The old text-based frontend remains usable during migration; no feature is removed merely because a new parser can recognize it.

“Flawless” is not a realistic guarantee. The target is predictable behavior backed first by the shipped `stdlib/` and `examples/` continuing to transcode, compile, and run their tests, then grammar conformance, mapped diagnostics, bounded migration comparisons, fuzzing, and measured performance. Tree-sitter is a parser/CST engine, not the semantic AST, type checker, preprocessor, or C backend.

## Target pipeline

```text
project/import graph
  -> immutable source snapshots and coordinate maps
  -> selectable parser backend
  -> lossless C-plus CST with recoverable syntax diagnostics
  -> normalized C-plus AST and symbol/type model
  -> comptime/import expansion to a fixed point
  -> semantic validation and runtime lowering IR
  -> C AST / structured C emission with source map
  -> existing external C compiler (TCC, CC, or configured compiler)
```

Each stage consumes an explicit value and returns an explicit value plus diagnostics. Stages do not discover structure by rewriting arbitrary substrings. Generated syntax is parsed again at the phase boundary where it becomes active. The C compiler remains the authority for C ABI details and final C validity.

## Component specifications and solution sketches

### 1. Source manager and source snapshots

Own canonical source identities, immutable file contents, revisions, import relationships, and encoding/coordinate conversion. A snapshot exposes C-plus UTF-16 offsets used by current Kotlin code, UTF-8 byte offsets used by Tree-sitter, and line/column spans. A parser node span must always map back to a source snapshot; generated text carries origin segments rather than fabricated file positions. Cache a snapshot for unchanged content and increment its revision when content changes. Imports are resolved by a separate policy using project roots, standard-library roots, and relative paths.

Initial implementation adds `SourceId`, `SourceSnapshot`, `SourceCoordinateMap`, and `SourceManager`, reuses the existing `SourceFile` span model, and routes the root input through the manager. It deliberately does not yet replace comptime import loading.

### 2. Frontend backend contract and selection

Expose a narrow compiler API: parse a `SourceSnapshot` under an explicit dialect/target/options value and return a backend-neutral parse result, diagnostics, and backend identity. Backend implementations own lexing where their parser combines lexing and parsing. Selection is explicit (`legacy` or `tree-sitter`) through an internal compiler option; the CLI's `AUTO` mode attempts Tree-sitter first and retains legacy fallback during migration. Do not expose Tree-sitter `Node` or numeric symbol IDs to compiler passes.

Migration implementation: `CPlusParserShadowRunner` parses with an authoritative backend and an observational backend in one call. It records coverage, diagnostics, and normalized-node fingerprint differences, plus syntax-span parity for the comptime/test subset both implementations recognize, while preserving both results. Trailing whitespace accidentally included in legacy scanner spans is trimmed only for the comparison key. Its `errorLocationsAlign` metric requires a one-to-one matching between error ranges or zero-width insertion points from each backend; `errorSpansMatch` separately reports exact error-span multiset equality, and `diagnosticsMatch` compares full signatures as an order-independent multiset. Tests distinguish these strengths, including disjoint ranges, ambiguous overlap, and equal spans with different codes. The malformed function-parameter case has exact span parity after correcting the legacy scanner. Empty `comptime flags` and missing `comptime import` paths are structurally parsed and validated by both backends. The legacy shadow adapter can now mask each malformed top-level construct in a same-length scratch source and rescan, recovering subsequent diagnostics and unaffected node spans; six permutations of two malformed directives and a valid declaration retain exact diagnostics and the valid node's source range. This does not alter fail-fast production evaluation. The CLI exposes `parse --backend legacy|tree-sitter`; ordinary `transcode`, `compile`, `run`, and `test` use AST-first `AUTO` selection with a documented legacy compatibility fallback, while explicit `--frontend=tree-sitter` remains strict. Shared-construct parity covers all current C-plus files under `stdlib/` and `examples/`; the repository corpus now also requires both parsers to report no errors or recovery nodes and exact error-span parity. Both transpilers' output for the representative real modules compiles as C11 on the local host, and the AST prototype now extends host C11 syntax checking to all 62 repository C-plus sources; this required adding the missing `<stddef.h>` dependency to `wctype.cp` and making the zero-valued `FLAG` used by `examples/annotated.cp` explicit. Runtime comparison now includes static factories and pointer receivers, `@throws(error)` calls through both free functions and methods, with generated declarations mapped to source, in addition to common-C function-pointer/control-flow and C11 declaration/initializer programs plus method, defer, error-return (`@throws()`), import, and composed method/try/defer cases. These fixtures compare exact stdout/status and selected source-map origins. Both common-C fixtures additionally compare token spellings after excluding whitespace, comments, and compiler-only `#line` directives; those directives can split C grammar productions in generated source even though the host C compiler accepts them.

The malformed-diagnostic slice now has exact signature parity for invalid comptime function parameters, empty compiler flags/import operands, and missing closing braces in comptime blocks, `@test` bodies, and legacy `@type` generators. Tree-sitter uses header context to normalize the invalid parameter token without changing body diagnostics; missing-brace nodes are contextualized from their enclosing C-plus node at EOF. These six forms are still a deliberately bounded error corpus: general C grammar error recovery, arbitrary malformed C-plus diagnostics, whole-language AST/output parity, and cross-platform execution remain open migration gates.

### 3. Tree-sitter C-plus grammar module

Keep the upstream C grammar, license, provenance, pinned revision, generator version, and local changes together in a dedicated module. Extend its grammar to recognize valid C-plus constructs directly: struct-contained methods, annotations, receiver calls, comptime declarations/blocks/invocations, `defer`, checked error calls, and test fixtures. Define named nodes and fields for constructs consumed by later passes. Use external scanners only for lexical state that cannot be expressed cleanly in the grammar. Recovery `ERROR`/missing nodes are diagnostic input and a migration aid, never the normative C-plus syntax boundary.

Check generated parser artifacts into the repository (or make generation reproducible in CI from the pinned toolchain); regular compiler builds must not need a parser generator download. The reproducibility gate byte-compares generated `grammar.json`, `node-types.json`, and `parser.c` with their checked-in counterparts. Preserve upstream attribution/license and record the fork point. Build and package the Tree-sitter runtime and language parser for supported hosts, or select a compatible Kotlin/JVM binding after validating Java 21, native loading, and distribution size. The six-host CI matrix stages the grammar JNI libraries into the CLI JAR; release packaging checks their resource paths. This packaging decision is a phase gate, not an assumption, and host runtime checks still gate promotion.

### 4. CST-to-AST adapter

Translate grammar-specific concrete nodes into stable C-plus AST types with source spans and references to retained syntax/trivia where source-preserving output is useful. Normalize aliases and equivalent syntax once. The initial compiler-facing categories distinguish structs, unions, enums, enum lists and enumerators, typedefs, declaration/field lists, fields, variables, functions, methods, types, declarators, initializers, annotations, generic type parameters, attributes, designators, parameter/argument-list containers, comments, identifiers (including goto labels), control flow, preprocessor directives, and C-plus constructs. Common variadic parameters, bit fields, concatenated strings, assembly-expression parts, and ABI/preprocessor helpers map into these stable families while retaining their grammar kinds. Declaration classification follows C declarator binding order: a function-pointer object is a variable even though its type contains a function layer, while function prototypes and functions returning pointers remain functions. Original grammar names and source spans remain available on every adapted node. Unknown/recovered nodes remain representable and diagnostic-bearing; they must not be silently dropped. A dedicated AST schema and exhaustive adapter tests prevent generated grammar changes from cascading into every pass.

### 5. Module graph, preprocessing, and comptime

Represent source imports as a graph with canonical identities, cycle diagnostics, and deterministic dependency order. Keep ordinary C `#include` semantics delegated to the C compiler. Parse C-plus `comptime import`, resolve comptime definitions, evaluate permitted values, and materialize generated C-plus declarations until no active comptime forms remain. Generated declarations are parsed on the next expansion iteration, with origin segments chained to the generator call/body. The evaluator stays sandboxed and bounded as specified in `SPEC.comptime.md`; it consumes AST nodes rather than rescanning source text.

Current transition: the established evaluator remains the production authority and the compilation result exposes canonical import edges and dependency-first `sourceOrder` metadata via `TranscodedSource`. The Tree-sitter prototype now resolves module-scope modern `comptime import` and legacy C-plus `@import` nodes through the shared path resolver, leaves nested generator-body imports dormant, diagnoses imports in runtime scopes, deduplicates modules, rejects cycles, materializes supported OS conditions before import discovery, emits dependencies before importers, and preserves each module's source origins. It also lowers parsed C `@import("...c")` nodes to ordinary absolute `#include` directives. Tests cover nested relative/`stdlib:/` imports, duplicate edges, cycle spans, imported scalar comptime values, imported test/assertion origins, and generated C execution. The experimental parser indexes legacy `@fn` generators, `typedef @generator(T) Alias;` specializations, and nested `comptime code` declarations; each nested construct records its nearest enclosing generator span and remains dormant until materialization. Generator signatures/result kinds, parameters, invocation spans, and aliases are retained in the AST index. The prototype materializes structural OS conditions (`os == "..."`, `os != "..."`), a bounded module-scope integer/bool scalar subset, pure scalar comptime functions with one return expression, and AST-indexed `comptime flags`; generated literals retain source origins and compiler options preserve first-seen order. G4.4 adds AST evaluation of `T.name`, target-ABI `T.size`/`T.align` for primitive types, primitive/pointer typedef aliases, and ordinary standard-layout structs, plus bounded `Struct.fields` iteration for simple, pointer, fixed-size/multidimensional array, pointer-array, function-pointer, and named/unnamed bitfield fields with `.name`, `.type`, `.annotations`, `.annotationsText`, `.flag`, `.width`, `.offset`, `.size`, and `.align`, plus string-returning identifier splices. Annotation iteration yields structured values with `.name`. Width expressions retain source mapping and can be evaluated when passed to scalar entity parameters if they fit the bounded evaluator; packed/aligned layouts, unions, bitfields for layout queries, flexible arrays, incomplete fields, architecture predicates, and general compile-time evaluation remain incomplete. Generic entity/code invocations now accept AST-validated abstract pointer, array, and function types; scalar generator arguments also use AST evaluation with previously declared module comptime values and pure scalar functions. The scalar and field-loop reflection paths share one target-aware ABI layout model, and each supported slice has focused materialization and C compile/run tests. Target layouts are explicit and unsupported targets fail closed with mapped diagnostics. Unsupported condition/value forms and out-of-scope flags fail closed; the prototype does not change production resource limits. `cplus graph file.cp` serializes import metadata as `cplus.imports.v1`; VS Code, IntelliJ, and Vim import-graph actions consume the graph and navigate to selected imports. Runtime emission remains dependency-first as before; the JSON projection does not change generated C.

**Current G4.4 reflection increment:** the verified field-loop subset includes independently scoped nested `.fields` and per-field `.annotations` loops, structured annotation values with `.name`, an explicit `.annotationsText` projection, unnamed bitfields (`.name` is empty; `.type` is the declared base type), bitfield metadata (`.flag`, `.width`), and standard-layout aggregate metadata (`.offset`, `.size`, `.align`). The shared ABI model accounts for scalar, pointer, nested-struct, fixed-size-array fields, C padding, and final aggregate alignment on x86_64/arm64 Linux, Windows, and macOS targets. Width expressions are preserved with source origins and can flow through scalar entity arguments when supported by the bounded integer/bool evaluator; ordinary fields report false/zero. Nested expansion has a fixed total-item budget so reflected Cartesian products cannot grow without bound. Only type `.fields` and field `.annotations` are iterable; arbitrary expressions fail closed at the iterable span. Packed/aligned structs, unions, bitfields for layout queries, flexible arrays, and incomplete fields remain unsupported. This supersedes earlier status text that listed aggregate layout and structured annotations as unsupported.

**Current entity-argument increment:** scalar generator arguments use the AST comptime evaluator and its module-scope value/function environment, rather than a separate literal parser. Invocation indexing now limits `argument_list` discovery to direct invocation children, preventing nested runtime-call arguments from truncating an outer comptime argument. Tests cover a reflected arithmetic bit width, `double_value(base_value) + 2`, source-origin retention, and mapped overflow rejection. C target integer-width and promotion parity remain open.

**Current scalar conditional increment:** AST `conditional_expression` nodes are evaluated by their named condition/consequence/alternative fields, and only the selected arm runs. A generated-entity fixture places division by zero in each unselected arm and compiles/runs the resulting C; a string-valued condition is rejected with a mapped diagnostic rather than treated as false. Existing `&&`/`||` short-circuit behavior and the new conditional behavior are documented; full C conversion/promotion equivalence remains open.

**Current scalar-string increment:** the AST evaluator supports ordinary quoted C string literals, concatenation with comptime `+`, and simple C escapes, with mapped failure for unsupported escapes. Comptime strings materialize as target-stable UTF-8 bytes; non-ASCII/non-printable bytes use exact three-digit octal escapes in generated C. The legacy renderer received the control-character fix used by the ASCII differential fixture. C hex/octal/UCN escapes and `L`/`u8`/`u`/`U` prefixed literals are explicitly unsupported with mapped diagnostics; UTF-16/32 and wide values use runtime encoding APIs rather than implicit comptime coercion.

**Inline-expression parity increment:** the legacy inline-comptime scanner no longer requires the expression's first token to be an identifier. Literal- and parenthesized-leading scalar expressions now pass through both frontends, and a shared fixture checks both generated forms and equivalent host-C executable results. This closes that narrow syntax mismatch only; broad evaluator parity remains open.

**Current scalar-evaluator increment:** scalar integer evaluation uses arbitrary precision internally and materializes only within the selected target C integer type. Literal overflow beyond `unsigned long long`, signed arithmetic overflow, MIN/-1 division/remainder, and unsafe signed shifts fail with mapped diagnostics. The typed-integer increment below adds a bounded target model for literal selection, promotions, conversions, and unsigned shifts; full C constant-expression parity remains unverified.

**Current scalar-operator evidence:** unary `+`, `-`, `!`, `~` and the implemented arithmetic, comparison, logical, bitwise, and shift operators are materialized in focused fixtures, then compiled and checked against the same ordinary C expressions on the host compiler. The legacy comptime evaluator rejects `~`, so it is not a complete oracle for this operator set; do not treat legacy acceptance as a gate for newly supported prototype syntax. The bounded target-width/promotion slice, including the complete supported `unsigned long long` domain, is covered below; external-host ABI parity remains open, while the comptime string encoding boundary is closed above.

**Current typed-integer increment:** module-scope comptime integer declarations now carry a bounded target-aware type model. The evaluator retains values as arbitrary-precision integers until conversion; signed declarations are range-checked, unsigned declarations use C-style modulo conversion through the full supported `unsigned long long` width, and `_Bool`/`bool` declarations normalize to `0` or `1`; `long` follows the selected target model (32-bit on Windows, 64-bit on the supported Unix targets). Plain `char` is modeled as unsigned only for Linux arm64 and signed for the supported Linux x86_64, macOS, and Windows target pairs; unknown target combinations fail closed rather than guessing. Literal candidates are selected by radix and suffix, then comptime comparisons and bounded arithmetic select a common integer type using the modeled C usual-conversion rules, including small-integer promotion and mixed signed/unsigned width comparison. Unary integer operators, shifts, integer casts, and scalar-function parameter/result conversions preserve the promoted/left-operand, cast-target, or declared-function type, with unsigned modulo behavior and fail-closed signed rules. Signed arithmetic overflow is diagnosed with the original expression span, while unsigned arithmetic wraps. This is deliberately a semantic slice, not full C constant-expression parity: pointer/non-integer casts and cross-host compiler evidence remain migration gates.

### 6. Name resolution and semantic model

Build scopes and symbol tables for C declarations, typedef names, structs, fields, methods, static methods, comptime names, and annotations. Runtime semantic indexing must exclude dormant declarations inside comptime generators/blocks/conditionals and become aware of generated declarations only after materialization and reparsing. Resolve `receiver.method(...)` against declared receiver types and pointer/value forms while preserving pointer depth through typedef aliases, parameters, and fields; a pointer-to-pointer is not treated as a direct instance, while explicit dereference can recover the pointee receiver. Inside an instance method, infer an untyped `self` receiver from its enclosing struct. Explicit parenthesized `&value` and `*pointer` receiver expressions are normalized for type lookup; chained field receivers are resolved through declared field types, and already-pointer receivers are passed without adding another address operator. Preserve ordered C declarator shape and original parameter spellings, including qualified method parameters and nested inline callback signatures, so later passes do not have to reconstruct pointer/qualifier placement from a flattened type name. Preserve an explicit distinction between `@throws()` (error-return) and `@throws(name)` (error-out), with the annotated declaration's parameter symbols available for validation and call rewriting. Resolve `@throws` declarations to call sites, validate catch codes/parameters, and retain ownership/access annotations as metadata without enforcing them unless the language specification later changes. C preprocessor expansion is not reimplemented here; unresolved macro-dependent C constructs remain delegated to the C compiler or receive explicitly documented limits.

The opt-in semantic prototype reports known receiver-kind errors: static methods used through values and instance methods used through type names. It also recognizes the established explicit-receiver form `Type.instance_method(&value, ...)` when the first argument resolves to a single pointer of the qualified type; this is distinct from a static call and lowering must not synthesize a second receiver. Callable declarations now retain a bounded return base type and post-call declarator shape, allowing a known function or static method result to become the receiver of a chained call such as `make_widget()->add()`. Conflicting declarations and unsupported callable return shapes remain unresolved. File-scope value declarations seed receiver lookup (including simple declarations nested in preprocessor branches), while typedef names do not enter value scope; comma-separated object declarators are indexed individually. Ordered pointer/array/function declarator layers preserve distinctions such as an array of pointers versus a pointer to an array through aliases, variables, parameters, and fields. Subscript expressions consume one outer array/pointer layer, supporting value arrays, arrays of pointers, pointer-to-array and multidimensional forms. Receiver validation considers the complete remaining declarator shape: `.` requires a value receiver, while `->` accepts a direct pointer or a C array-of-struct expression that decays to that pointer; arrays of pointers and pointers to arrays must be indexed or dereferenced first. Conditional receiver expressions propagate a known type only when both arms agree or the other arm is a syntactic C null pointer constant. The explicit C-plus `(&value).method()` form remains supported, while pointer-to-pointer receivers require explicit dereference. Receiver-kind/operator/depth/declarator-shape diagnostics retain the call span and cause the experimental transpiler to fail closed. `for` initializer declarations have a dedicated scope visible to the condition, update, and body but not to following statements. This supports singleton-style C-plus wrappers such as xmem and ordinary C declarations such as `widget_t value, *pointer;`. Unknown external members and macro-dependent receiver types remain unresolved rather than being guessed.

Initial semantic support also records function-pointer typedefs as callable signatures, preserving the base result type, parameter names/base types and original parameter declaration spellings, variadic marker, and declarator span. The typedef symbol retains its exact original declaration text and ordered `CPlusDeclaratorLayer` shape so pointer/qualifier placement is not lost while deeper declarator normalization is incomplete. Struct-method and global-function parameters now retain the same declaration spelling and recursively nested callback metadata, including qualified forms such as `const widget_t * restrict source`; an inline callback exposes `[POINTER, FUNCTION]` rather than a flattened pointer count. Callback signatures nested in function-pointer parameters and returned-function-pointer composition are indexed recursively, and abstract pointer/array/function layers are retained for cast and compound-literal type descriptors; C11 fixtures exercise these declarations and attributes by compiling/running with each locally available `cc`, `gcc`, and `clang` driver. Named inner function declarators are selected for declarations whose return type is itself callable, so a method such as `int (*select(borrowed *self))(int)` keeps its full C declarator when lowered instead of being flattened to a scalar or direct-pointer return. Declarator-owned GNU/MS attributes and calling-convention modifiers are now retained as source-spanned `CPlusDeclaratorQualifier` metadata on symbols, parameters, and callable signatures; the lowering pass relocates suffix attributes to a legal C function-definition position when necessary. This is a bounded preservation/modeling slice, not a claim that every target ABI or calling convention is semantically validated. Active comptime invocations now bind to indexed generator declarations by symbol and arity, producing mapped unresolved/arity/ambiguity/duplicate diagnostics while ignoring nested dormant generator syntax; entity materialization uses that same arity key, so same-name generators with different signatures expand deterministically. Generator definitions inside runtime functions/struct bodies are excluded from the module comptime namespace, while runtime invocations can bind to module-level declarations. This is declaration binding only: the legacy evaluator remains authoritative for argument typing/evaluation and materialization. The opt-in allocation analyzer validates known provenance for annotated global/method parameters and function/method returns, plus owned double-pointer outputs, and carries explicit annotated call-return domains into surrounding arguments. Its branch joins compare allocation domains rather than allocation-site text; sequenced comma writes update flow, while `&&`/`||` and conditional-expression joins discard provenance when a path may skip or disagree. Function-call arguments are analyzed on independent snapshots, and potentially conflicting writes invalidate stale prior provenance. Calls passing `&variable` to annotated owned double-pointer parameters conservatively invalidate caller provenance unless the incoming and declared output domains agree; unannotated double-pointer parameters and unresolved calls receiving `&variable` are treated as possible pointer-output writes and also invalidate provenance. Compound assignments and prefix/postfix updates now explicitly invalidate the modified lvalue's provenance instead of carrying a stale allocator domain through pointer arithmetic or mutation. Structured `while`/`for`/`do` transfers now iterate to a bounded allocation-domain fixed point: `while`/`for` include the zero-iteration path, `do` includes its required first iteration, and converged equal-domain exits retain provenance. Loops with unmodeled exits/labels or failure to converge conservatively invalidate written outer variables; `for` initializer declarations remain local. General unsequenced binary operand combinations remain unmodeled. Explicit type-qualified instance calls align the explicit receiver separately from user arguments for allocation-contract checks. It does not yet validate function-pointer assignments or all qualified/deep declarator compatibility; cross-host compiler verification remains a gate.

Switch cases are now diagnostic-walked independently from conservative snapshots in a local scope; provenance for any outer pointer assigned in the switch, including one potentially written through an annotated owned double-pointer call such as `replace(&value)`, is invalidated afterward because cases may be skipped or fall through. This prevents one case's assignment from becoming a false assumption in a sibling case, but remains one-pass analysis rather than a case-sensitive switch data-flow solution.

The allocation-flow prototype now treats assignment operands, subscript operands, and initializer-list elements as independent possible paths when C leaves their evaluation order unspecified. This extends its conservative side-effect handling without claiming a complete unsequenced-expression model; broader expression ordering and full declarator compatibility remain migration gates.

The migration corpus also records an intentional legacy-analysis limitation: the
scanner can report a loop-body allocator assignment as a mismatch at a later
declaration even when the loop has a zero-iteration path. The AST fixed-point
analysis preserves the incoming provenance in that case and therefore does not
copy the scanner's false-positive diagnostic. Exact diagnostic parity is required
for bounded equivalent-flow fixtures; this divergence stays visible until an
independent ownership-diagnostic contract replaces both implementations.

Test declarations are treated as function closures during AST defer and checked-call
lowering. The generated `cplus_test_finish` label is placed before a fixture's
deferred cleanup tail, so assertion failure paths execute cleanup exactly once. The
test differential excludes only harness-owned initialization ordering and compares
the remaining normalized fixture/harness tokens plus a runtime failure-cleanup case.

### 7. Lowering IR and ordered transformations

Use typed, source-spanned runtime IR (or a normalized AST with explicit lowered nodes) for C-plus-only behavior. Lower in named, testable passes: implicit receiver insertion/method names; `defer`; `try`/`catch`; test harness extraction; and optional allocation diagnostics. Each pass declares prerequisites and invariants, returns diagnostics, and preserves source origins. The prototype now uses `CPlusAstLoweringPipeline` to execute ordered transformations, enforce AST/source snapshot agreement, reparse changed results before the next pass, record pass traces, and stop immediately on lowering or parser errors. This is a safe orchestration layer over AST transformations, not yet the dedicated typed lowered-node IR described here. The transition prototype extracts/validates `@throws` metadata and AST-lowers standalone checked calls plus error-out assignment/initializer values through nested ordered catches. It also has an opt-in AST allocation-intent analyzer for annotated-variable mismatches, direct allocator calls, simple initializer aliases, standalone direct identifier assignments, annotated global-function parameter and return checks (combining prototype/definition contracts), owned double-pointer output writes, resolved instance/static method parameter checks, and annotated method return checks using known allocator/parameter provenance. Explicit call-return domains propagate to surrounding argument checks. An `if/else` join retains provenance only when both paths agree (a missing `else` is the unchanged incoming path), and a conditional expression has known provenance only when both value arms agree; divergent branches, loops, and short-circuit assignments remain unknown. Larger checked-call expressions fail with mapped diagnostics. Comptime syntax is absent before runtime lowering. Avoid serial string replacements for semantics or control flow.

### 8. C representation, emitter, maps, and diagnostics

Emit C from structured nodes with a mapped writer. The output map records generated byte/line ranges to original snapshots and spans, including generated text with multiple contributing origins. Origin lookups use half-open character offsets; the legal EOF boundary has no character origin and must return `null` rather than indexing past the buffer. Continue emitting `#line` for compiler compatibility, but use the explicit map to normalize compiler diagnostics precisely. Keep diagnostic severity, code, related spans, and notes independent of terminal formatting. Preserve the public `TranscodedSource`/CLI behavior as a compatibility facade while its internals migrate.

Current transition: fixture and `@throws` removal, `defer` placement, struct-method extraction, receiver-call lowering, and checked-call/try-catch lowering in the experimental pipeline use node-keyed replacements and before/after-node insertions through mapped AST traversal. Nested receiver calls are rendered recursively within their owning call-expression node; nested try nodes and checked-call statements are replaced inside mapped AST subregions, preserving untouched trivia and origin segments. The prototype's final C stage traverses normalized AST terminals, emits exact token spellings with deterministic brace/statement layout, parenthesis-aware semicolon handling, AST-context punctuation, and indentation, preserves token origins, and leaves preprocessor regions verbatim. It reparses the final output before exposing it and rejects recovered, opaque, or unlowered C-plus nodes. Full grammar-aware formatting and semantic generation for all C nodes remain open; allocation analysis remains separate and production transpilation remains on the legacy emitter.

The final emitter must treat a C literal as a single spelling unit: Tree-sitter exposes string quotes, content, escapes, and character literal components as children, but adding layout between those children changes runtime values. Initial executable differential fixtures compile the same method/receiver, `defer`, and checked-call programs through both paths and compare exact stdout and exit status; the method fixture also checks generated source-map locations. They cover a format string, adjacent string literals, an escaped character literal, reverse-order deferred work, and caught error propagation across consecutive `@try` statements. The grammar treats `@try` and `@catch` as atomic keywords so comptime interpolation cannot recover across adjacent handlers. Broader syntax, diagnostics, and target coverage still gate promotion.

Test-runner parity now compares legacy scanner discovery against Tree-sitter AST extraction for named and identifier fixtures. Both harnesses compile and execute the same fixtures—including a struct method call—and agree on fixture names, per-fixture assertion counts, exit status, and exact output. The Tree-sitter fixture body and assertion spans are checked against their original offsets, and the emitted harness assertion maps back to its original `.cp` line. This is a supported-syntax regression, not yet general test-body AST lowering.

Mapped diagnostics are checked for columns as well as filenames and lines after method extraction. The final prototype emitter keeps at least the source line's original leading columns when normalized formatting would otherwise shift a compiler error; a differential C11 regression confirms both frontends report the same unresolved identifier location. Full column mapping across arbitrary rewrites and compilers remains an open gate.

Imported-source differential fixtures now check the same nested module graph through both frontends: canonical dependency order, mapped declaration origin, runtime output, and compiler error location in the imported `.cp` file. This is a local host-C11 gate for one import/scalar slice, not proof of all import forms or cross-host diagnostic parity.

For the experimental test path, supported scalar comptime expressions must materialize before AST fixture extraction. Otherwise fixture bodies bypass later runtime-source materialization and reach the harness with unresolved `comptime` syntax. The pass order now reparses the materialized source and extracts fixtures from that mapped revision; source origins inside root and imported fixtures remain attached to their original expressions. General generator-valued fixture content is still subject to the prototype's fail-closed boundary.

The prototype also unwraps top-level comptime blocks after selecting supported OS branches when the remaining content consists of compiler flags, supported integer/bool scalar declarations, scalar expression statements, entity invocations, or nested comptime blocks. Scalar expression statements are evaluated and discarded, including references to preceding scalar declarations in the same block; invalid scalar evaluation reports a mapped diagnostic rather than retaining the expression as runtime C. A scalar declared inside a top-level expansion block can feed a scalar entity invocation; the evaluator handles the grammar's ambiguous type-shaped identifier node only when the generator parameter is scalar, and a typedef-name negative fixture ensures type syntax is not accepted as a scalar value. An import interaction test passes a dependency's scalar through a root block into a dependency's code generator, then checks dependency-first emission, runtime behavior, and the generated literal's root-invocation source origin. Imports inside top-level C preprocessor guards retain module scope; the real Raylib facade and Snake example provide an AST transcode interaction covering dependency order, flags, methods, and fixture extraction. Runtime-function local comptime declarations remain explicitly rejected. The scalar and flags passes materialize selected values/options, and differential tests verify equivalent Linux/Windows options and runnable output where both paths accept the syntax. Ordinary runtime declarations and unsupported expressions inside these blocks remain mapped errors rather than leaking into C; arbitrary statement evaluation remains outside the prototype.

### 9. IDE and tooling consumers

Use the parser contract and shared node names for indexing, outline, navigation, completion, test discovery, and diagnostics. `cplus parse file.cp [-o ast.json]` exposes the versioned normalized result for saved files, while `cplus parse --stdin --source file.cp` parses an unsaved editor snapshot; `cplus graph file.cp` exposes resolved imports as `cplus.imports.v1`. VS Code and IntelliJ **Show Import Graph** actions consume the graph, while Vim's `:CPlusImportGraph` presents imported files in its location list; VS Code also projects a current normalized parse tree into outline symbols and Test Explorer fixtures when parser diagnostics are enabled, with its lightweight index/scanner as fallback. Vim exposes a normalized-AST location-list outline through `:CPlusSymbols`; both parse and symbols commands pass live buffer contents through stdin.
